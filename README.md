# کافه دانش | وب‌سایت خدمات دیجیتال

وب‌سایت فارسی کافه دانش با معماری **Next.js App Router**، رابط راست‌چین، صفحات خدمات، وبلاگ، نمونه‌کارها و پنل مدیریت محتوا.

## فناوری‌ها

- Next.js 16، React 19 و TypeScript
- Tailwind CSS و shadcn/ui
- Prisma ORM و SQLite برای توسعه محلی
- فونت محلی Vazirmatn

## پیش‌نیازها

- Node.js نسخه ۲۰.۹ یا جدیدتر؛ ترجیحاً نسخه LTS
- npm
- دسترسی اینترنت برای نصب بسته‌ها

## اجرای محلی در ویندوز

از CMD در پوشه پروژه اجرا کنید:

```cmd
npm install
copy .env.example .env
mkdir db
notepad .env
```

در فایل `.env`، مقدارها را متناسب با محیط خود تنظیم کنید. برای دیتابیس SQLite محلی، مسیر زیر با ساختار فعلی پروژه سازگار است:

```dotenv
DATABASE_URL="file:../db/custom.db"
NEXT_PUBLIC_SITE_URL="http://localhost:3000"
```

اگر `.env` از قبل دارید، آن را بازنویسی نکنید؛ فقط مقدارهای لازم را بررسی و اصلاح کنید. کلیدهای محرمانه و رمزهای واقعی را در Git قرار ندهید.

سپس اجرا کنید:

```cmd
npx prisma validate
npx prisma generate
```

### دیتابیس تازه و خالی

فقط برای نصب تازه که هنوز دیتابیس حاوی اطلاعات ندارید، اجرا کنید:

```cmd
npx prisma db push
npx tsx prisma/seed.ts
```

Seed محتوای اولیه تعریف‌شده در پروژه را وارد می‌کند. آن را فقط یک‌بار روی دیتابیس خالی اجرا کنید. اگر دیتابیس فعلی‌تان مقاله، نمونه‌کار، پکیج یا اطلاعات کاربران دارد، پیش از اجرای `db push` یا Seed نسخه پشتیبان بگیرید و بدون بررسی این فرمان‌ها را اجرا نکنید.

### اجرای سایت

در ویندوز، برای اجرای محیط توسعه از دستور زیر استفاده کنید:

```cmd
npx next dev -p 3000
```

سایت در [http://localhost:3000](http://localhost:3000) در دسترس خواهد بود. برای توقف سرور، در همان ترمینال `Ctrl + C` را بزنید.

## صفحات و قابلیت‌ها

- صفحه اصلی، درباره ما، تماس، پرسش‌های متداول و درخواست مشاوره
- صفحات خدمات: طراحی سایت، فروشگاه اینترنتی، سئو، تولید محتوا، هوش مصنوعی، UI/UX، بهینه‌سازی سرعت و پشتیبانی
- وبلاگ، صفحه جزئیات مقاله و نمونه‌کارها
- پنل مدیریت برای مقالات، دسته‌بندی‌ها، رسانه‌ها، نمونه‌کارها، پکیج‌ها، FAQ، درخواست‌های مشتریان، تنظیمات، کاربران و فعالیت‌ها
- متادیتای صفحات، canonical، Open Graph، sitemap و robots

قابلیت‌هایی که به سرویس خارجی نیاز دارند، از جمله اتصال مدل هوش مصنوعی یا درگاه پرداخت، تنها پس از تنظیم معتبر متغیرهای محیطی و تکمیل پیکربندی مربوطه قابل استفاده‌اند. وجود فایل یا رابط کاربری به‌تنهایی به معنی فعال بودن یک سرویس خارجی نیست.

## متغیرهای محیطی

فایل `.env.example` الگوی تنظیمات است. فایل واقعی `.env` را در ریشه پروژه نگه دارید و هرگز آن را Commit یا منتشر نکنید.

| متغیر | کاربرد |
|---|---|
| `DATABASE_URL` | اتصال دیتابیس؛ در توسعه محلی SQLite |
| `NEXT_PUBLIC_SITE_URL` | دامنه پایه برای متادیتا و نقشه سایت |
| `ADMIN_PASSWORD` | در صورت پشتیبانی Seed، رمز اولیه مدیر؛ فقط برای راه‌اندازی محلی و محرمانه |
| `ZAI_API_KEY` | کلید سرویس هوش مصنوعی، در صورت استفاده |
| `ZARINPAL_MERCHANT_ID`، `IDPAY_API_KEY`، `ZIBAL_API_KEY` | اطلاعات درگاه پرداخت، فقط پس از فعال‌سازی و دریافت کلید معتبر |

کلیدها و گذرواژه‌های واقعی را در این فایل راهنما، سورس‌کد، GitHub یا پیام‌های عمومی ننویسید. در محیط استقرار، آن‌ها را در بخش Environment Variables سرویس میزبانی تنظیم کنید.

## پنل مدیریت

مسیر ورود: `/admin/login`

حساب مدیر را مطابق خروجی یا فایل محرمانه‌ای که هنگام راه‌اندازی Seed ایجاد شده است دریافت کنید. پس از اولین ورود، رمز اولیه را تغییر دهید. اطلاعات ورود را در مخزن Git قرار ندهید.

نقش‌های تعریف‌شده در سیستم:

- **ADMIN:** مدیریت کامل
- **EDITOR:** مدیریت محتوای سایت
- **AUTHOR:** ایجاد و ویرایش مقاله‌های مجاز

## استقرار روی GitHub و Vercel

### GitHub

پیش از Commit بررسی کنید که موارد زیر در مخزن ثبت نشوند:

- `.env` و هر فایل دارای کلید API یا رمز عبور
- فایل‌های دیتابیس مانند `*.db` و `*.sqlite`
- فایل‌های محرمانه راه‌اندازی مانند `OWNER-INFO.md` و `ADMIN-LOGIN-INFO.txt`
- `node_modules`، خروجی `.next` و لاگ‌ها

مخزن را در صورت وجود اطلاعات داخلی یا کد اختصاصی، Private نگه دارید. فایل `.env.example` فقط باید مقادیر نمونه و بدون راز واقعی داشته باشد.

### Vercel و دیتابیس تولید

پروژه فعلی برای توسعه محلی از SQLite و مسیر فایل استفاده می‌کند. **پیش از استقرار عملیاتی روی Vercel، آن را به دیتابیس پایدار میزبانی‌شده—برای مثال PostgreSQL—منتقل کنید** و مدل Prisma، متغیرهای محیطی، داده‌ها و روند Migration را متناسب با دیتابیس جدید تنظیم کنید.

همچنین فایل‌سیستم محلی برای نگهداری پایدار فایل‌های آپلودی مناسب نیست؛ برای رسانه‌های پنل از فضای ذخیره‌سازی پایدار مانند Blob/Object Storage استفاده کنید. تا پیش از تکمیل این تغییرات و آزمایش فرم‌ها، ورود مدیریت، ثبت محتوا و ذخیره‌سازی، استقرار را نسخه آزمایشی در نظر بگیرید و آن را به‌عنوان نسخه عملیاتی نهایی معرفی نکنید.

## بررسی‌های پیشنهادی پیش از انتشار

```cmd
npx prisma validate
npx prisma generate
npm run lint
npm run build
```

اسکریپت‌های Build/Start پروژه ممکن است در ویندوز به ابزارهای خط فرمان سازگار با Unix وابسته باشند. در صورت خطای `cp`، `tee` یا `bun`، ابتدا اسکریپت‌های `package.json` را برای محیط هدف اصلاح کنید؛ موفقیت اجرای توسعه به‌تنهایی تأییدکننده Build یا استقرار عملیاتی نیست.

## پشتیبان‌گیری

پیش از تغییر Schema، انتقال دیتابیس یا Seed مجدد، از دیتابیس و فایل‌های رسانه نسخه پشتیبان بگیرید. از فرمان‌های دارای `--accept-data-loss` روی دیتابیس دارای اطلاعات واقعی استفاده نکنید، مگر اینکه پیامدها را بررسی کرده و نسخه پشتیبان قابل بازیابی داشته باشید.
