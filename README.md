# وب‌سایت کافه‌دانش — نسخهٔ Astro (استاتیک + SSR + پنل مدیریت ابری کامل)

سایت کامل کافه‌دانش با [Astro](https://astro.build) — همهٔ صفحات **استاتیک و سریع**، اما مجله، صفحات مقاله‌ها، صفحات ابری، نقشهٔ سایت و APIهای پنل **سمت سرور رندر می‌شوند**: هر مقاله یا صفحه‌ای که در پنل «انتشار» می‌شود، همان لحظه با HTML واقعی برای **همهٔ بازدیدکنندگان و گوگل** قابل خواندن است (بدون نیاز به جاوااسکریپت).

---

## ۱) اجرا روی سیستم خودت

پیش‌نیاز: [Node.js](https://nodejs.org) نسخه ۱۸ یا بالاتر

```bash
npm install      # نصب وابستگی‌ها (فقط یک بار)
npm run dev      # اجرای محلی روی http://localhost:4321
npm run build    # ساخت خروجی نهایی در dist/
```

## ۲) انتشار — مخزن گیت‌هاب + ورسل (همان مسیر فعلی)

با هر push به مخزن `rasoolbahadran-stack/cdanesh`، ورسل خودش سایت را می‌سازد و منتشر می‌کند (۲–۳ دقیقه). دامنهٔ cdanesh.ir قبلاً متصل است.

**به‌روزرسانی با GitHub Desktop:** محتوای پوشهٔ `cdanesh-astro` داخل ZIP (نه خود پوشه) را داخل مخزن کلون‌شده کپی کن (به‌جز پوشهٔ پنهان `.git`) → Commit → Push. پوشهٔ `node_modules` را جابه‌جا نکن.

## ۳) فعال‌سازی انتشار واقعی (یک‌بار — مهم‌ترین گام)

> **پنل خودش راهنمایی می‌کند:** وقتی وارد `/admin` شوی و فضای ابری وصل نباشد، بنر زرد راهنمای سه‌گامی بالای داشبورد نمایش داده می‌شود.

| گام | کجا | چه کار |
|---|---|---|
| ۱ | ورسل → پروژه → تب **Storage** | **Create Database** → نوع **Blob** → نام `cdanesh-content` → **Connect** به همین پروژه |
| ۲ | تب **Settings → Environment Variables** | متغیر `ADMIN_PASSWORD` با یک رمز قوی (حداقل ۱۰ کاراکتر) — تیک Production و Preview → Save |
| ۳ | تب **Deployments** | آخرین دیپلوی → **⋯ → Redeploy** |

بعد از ۲–۳ دقیقه: خروج از پنل → ورود با `admin` و رمز ابری. نشان ذخیره‌سازی باید «ابری (واقعی)» شود. تا قبل از آن، پنل در حالت دمو است و تغییرات فقط در همان مرورگر ذخیره می‌شود.

## ۴) امکانات پنل مدیریت (`/admin`)

| بخش | توضیح |
|---|---|
| **داشبورد** | آمار کلی + نمودار ۱۴ روزهٔ پیام‌ها + نمودار دسته‌بندی مقالات |
| **مقالات** | ویرایشگر حرفه‌ای WYSIWYG + حالت کد HTML؛ دکمهٔ «انتشار»؛ زمان‌بندی؛ پیش‌نویس |
| **رسانه** | کتابخانه رسانه مثل وردپرس: آپلود تصویر/فایل در تب «🖼» ویرایشگر یا هنگام انتخاب تصویر شاخص؛ تصاویر بزرگ خودکار به WebP فشرده می‌شوند؛ کپی لینک و حذف |
| **تصویر شاخص** | انتخاب آزاد از کتابخانه رسانه یا هر آدرسی + فیلد Alt |
| **صفحات** | «صفحات ابری»: افزودن صفحه جدید (منتشر در `/p/<slug>`)؛ «شرایط استفاده» و «حریم خصوصی» هم از همین‌جا ویرایش می‌شوند؛ تب دوم: سئوی صفحات ثابت |
| **پیام‌ها** | پیام فرم تماس، درخواست مشاوره و درخواست پکیج + بودجهٔ اعلامی مشتری؛ وضعیت جدید/خوانده/پاسخ‌داده‌شده؛ خروجی JSON |
| **درگاه پرداخت** | ثبت لینک درگاه واسط (زرین‌پال و…)؛ دکمه‌های پرداخت سایت به همان لینک وصل می‌شوند |
| **سؤالات متداول** | سؤال و پاسخ هر صفحهٔ خدمت؛ ترتیب و فعال/غیرفعال |
| **تنظیمات** | **تغییر نام کاربری و رمز عبور از خود پنل** (نشست‌های دستگاه‌های دیگر خودکار بسته می‌شود) |

**آدرس‌های مقاله:** هر مقاله در `/blog/<slug>` منتشر می‌شود و لینک «مشاهده در سایت» در فهرست مقالات همان را باز می‌کند. آدرس‌های قدیمی `/article?slug=…` به آدرس تمیز ریدایرکت ۳۰۱ می‌شوند.

## ۵) سئو

- **نقشهٔ سایت خودکار:** `cdanesh.ir/sitemap.xml` — مقالات ابری و صفحات ابری بلافاصله اضافه می‌شوند.
- **Robots:** `cdanesh.ir/robots.txt`
- **دادهٔ ساختاریافته:** Organization، Article، BreadcrumbList و FAQPage (سؤالات صفحات خدمات داخل HTML واقعی صفحه است).
- **عنوان‌های سئو** صفحات اصلی/خدمات با کلمات کلیدی هدف (طراحی سایت در بوشهر و…).
- **نام برند در گوگل:** اگر توضیح قدیمی («پلتفرم آموزشی») هنوز نمایش داده می‌شود، در [Search Console](https://search.google.com/search-console) → URL Inspection برای `/` و `/about` و `/services` «Request Indexing» بزن؛ چند روز تا چند هفته طول می‌کشد.

## ۶) نکته‌های امنیتی

- رمز مدیر فقط به‌صورت هش (pbkdf2) در فضای ابری ذخیره می‌شود؛ در کد نیست.
- محدودیت تلاش ورود، نشست ۷ روزهٔ امضاشده (HMAC)، تلهٔ اسپم و محدودیت نرخ فرم‌ها فعال است.
- هدرهای امنیتی (X-Frame-Options، nosniff، Referrer-Policy و…) در `vercel.json` تنظیم شده‌اند.
- **در ورسل چیز خاصی لازم نیست تیک بخوری:** فقط مطمئن شو «Deployment Protection» خاموش است (سایت عمومی بماند) و Blob + `ADMIN_PASSWORD` مطابق گام ۳ تنظیم باشند.

## ۷) ساختار پروژه

```
src/pages/          صفحات سایت (استاتیک) + blog/[slug] + p/[slug] + api/*  (SSR)
src/lib/            منطق SSR مقالات و صفحات ابری
src/data/           دادهٔ پایهٔ مقالات، FAQ، صفحات پایه
server/handlers/    APIهای ابری (مقالات، پیام‌ها، درگاه، صفحات، ورود)
public/assets/      CSS / JS / فونت / تصاویر (WebP)
```

## ۸) پس از استقرار — چک‌لیست تست

1. ورود به `/admin` با رمز ابری → نشان «ابری (واقعی)».
2. یک مقالهٔ تستی بنویس و «انتشار» بزن → در دستگاه/مرورگر دیگری `/blog` را باز کن — مقاله باید همین لحظه دیده شود.
3. از فرم «درخواست مشاوره» یک پیام تست بفرست → بخش «پیام‌ها» پنل.
4. یک صفحهٔ جدید بساز → لینک `/p/<slug>` را در مرورگر ناشناس باز کن.
5. PageSpeed Insights برای `/` و `/web-design`.
