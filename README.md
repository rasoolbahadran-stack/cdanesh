> کارت‌های نمونه‌کار با اسکرول عمودی هنگام Hover، تصاویر انسانی باکیفیت WebP) —
> همان اطلاعات، همان صفحات، همان پنل مدیریت و همان هویت برند کافه دانش.

## شروع سریع

```bash
# پیش‌نیاز: Node.js 18+ (پیشنهادی 22)
npm install

# توسعه محلی
npm run dev            # http://localhost:4321

# بیلد پروژه کامل (Vercel + پنل مدیریت + API)
npm run build

# بیلد استاتیک عمومی (بدون admin/api) برای بازبینی
npm run build:static   # خروجی: dist-static/
```

فایل `.env.example` را به `.env` کپی کنید و مقادیر را تکمیل کنید:

```env
SITE_URL=https://cdanesh.ir
DATABASE_URL=postgresql://...        # رشته اتصال Neon (اختیاری — بدون آن سایت با داده محلی کار می‌کند)
ADMIN_EMAIL=admin@cdanesh.ir
ADMIN_PASSWORD=رمز-قوی-مدیر
ADMIN_JWT_SECRET=یک-کلید-تصادفی-طولانی
VERCEL_DEPLOY_HOOK_URL=              # اختیاری — برای بازسازی خودکار پس از انتشار محتوا
```

## حالت‌های بیلد

| دستور | خروجی | کاربرد |
| --- | --- | --- |
| `npm run build` | `dist/` + آداپتور Vercel | استقرار کامل روی Vercel (شامل پنل مدیریت و API به‌صورت Serverless) |
| `npm run build:static` | `dist-static/` | نسخه استاتیک تمام صفحات عمومی برای بازبینی قبل از گیت — پنل و API کنارگذاشته می‌شوند و ساختار پروژه پس از بیلد بازیابی می‌شود |

در حالت کامل، صفحات عمومی **پیش‌رندر (static)** و مسیرهای `/admin` و `/api` **on-demand** سرو می‌شوند؛
یعنی همان الگوی هیبرید سایت فعلی با سرعت کامل صفحات عمومی.

## اتصال دیتابیس Neon

1. در پنل Neon رشته اتصال را کپی کنید و در `DATABASE_URL` قرار دهید.
2. اسکیما را یک‌بار اجرا کنید (مثلاً با `psql "$DATABASE_URL" -f db/schema.sql`).
3. رفتار پروژه:
   - **با DATABASE_URL:** صفحات عمومی هنگام بیلد از دیتابیس می‌خوانند؛ پنل مدیریت مقالات/نمونه‌کارها را در دیتابیس می‌نویسد؛ فرم‌ها در جدول `messages` ثبت می‌شوند.
   - **بدون DATABASE_URL:** سایت با «داده‌های محلی» کار می‌کند (فایل‌های `src/data/content/` که عیناً از آخرین وضعیت سایت فعلی استخراج شده‌اند) و فرم‌ها در لاگ سرور ثبت می‌شوند. هیچ‌چیز می‌شکند.
4. اگر دیتابیس فعلی کافه دانش ساختار/نام جداول متفاوتی دارد، فقط کوئری‌های `src/lib/db.ts` را با همان ساختار تطبیق دهید — بقیه پروژه تغییری نمی‌خواهد.

> **نکته مهم درباره محتوا:** تمام متن‌ها، مقالات، خدمات، تعرفه‌ها، سؤالات متداول و اطلاعات تماس
> از نسخه زنده cdanesh.ir استخراج و حفظ شده‌اند. تصاویر مقالات و خدمات هم منتقل شده‌اند؛
> تصاویر Hero/خدمات/درباره‌ما با نسخه‌های انسانی و باکیفیت WebP تازه تولید شده‌اند.

## پنل مدیریت

- آدرس: `/admin` (ورود: `/admin/login`)
- احراز هویت: JWT امضاشده در کوکی `httpOnly` (متغیرهای `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_JWT_SECRET`)
- محافظت: `src/middleware.ts` همه مسیرهای `/admin/*` و `/api/admin/*` را می‌پوشاند
- امکانات: داشبورد آماری، مدیریت مقالات (ایجاد/ویرایش/حذف/انتشار)، مدیریت نمونه‌کارها
  (با وضعیت انتشار و لینک نسخه زنده)، صندوق پیام‌های فرم تماس/مشاوره با علامت‌گذاری خوانده‌شده
- پس از تغییر محتوا برای به‌روزرسانی صفحات عمومی یکبار Redeploy کنید؛ اگر
  `VERCEL_DEPLOY_HOOK_URL` تنظیم شده باشد می‌توانید با یک فراخوانی هوک، بیلد جدید بگیرید.

## معماری زیردامنه نمونه‌کارها

هدف: نمایش زنده هر پروژه روی زیردامنه اختصاصی مثل `bazarino.cdanesh.ir`
بدون دست‌زدن به تنظیمات فعلی DNS و پروژه Vercel. مسیر پیشنهادی، سه گام اختیاری و برگشت‌پذیر است:

1. **DNS (پنل دامنه):** یک رکورد `CNAME` وایلدکارت به Vercel:
   `*  →  cname.vercel-dns.com.`
2. **Vercel (پروژه اصلی):** در Settings → Domains دامنه `*.cdanesh.ir` را اضافه کنید.
3. **ریدایرکت‌ها:** فایل `vercel.json` این پروژه الگوی ریدایرکت هر زیردامنه به نسخه زنده پروژه را دارد؛
   پس از فعال‌شدن وایلدکارت، ریدایرکت‌های زیر را از حالت کامنت خارج کنید:

```json
"redirects": [
  { "source": "/", "has": [{ "type": "host", "value": "bazarino.cdanesh.ir" }], "destination": "https://bazarino-astro-lva12s6uw-rasoolbahadran-stacks-projects.vercel.app", "permanent": false }
]
```

تا آن زمان، دکمه «مشاهده نسخه زنده» هر نمونه‌کار به همان URLهای Vercel فعلی (که همین حالا فعال‌اند)
وصل است و هیچ لینکی خراب نمی‌شود.

## وضعیت واقعی نمونه‌کارها

طبق بررسی نسخه زنده، ۱۴ صفحه نمونه‌کار منتشر شده است:

- **۱۱ پروژه با نسخه زنده روی Vercel** (بازارینو، مزون مهر، فروشگاه کفش، اسمارت گجت، ماه‌پوش،
  سیمبا بیوتی، اسمارتو، پورتال کارینو، آژانس نوین‌رشد، دو دموی کهکشانی) — badge سبز «نسخه زنده منتشر شده»
  و لینک مستقیم به نسخه زنده.
- **۳ نمونه مفهومی** (رُزا، آرمان، نِگار) — badge «نمونه مفهومی»؛ همان چیزی که سایت فعلی هم شفاف اعلام می‌کند.
- اسلاگ‌های قدیمی (`/portfolio/bazarino` و …) در `vercel.json` به اسلاگ‌های جدید ریدایرکت ۳۰۱ شده‌اند
  (در سایت فعلی این مسیرها به 404 می‌رفتند؛ این یک اصلاح SEO است).
- پیش‌نمایش کارت‌ها **اسکرین‌شات واقعی تمام‌صفحه** از خود دموهای زنده است (WebP بهینه)،
  با اسکرول عمودی نرم هنگام Hover و اسکرول خودکار آرام در موبایل.

## SEO و داده‌های ساختاریافته

- همه صفحات: canonical، متا دیسکریپشن، OG/Twitter کامل (مطابق سایت فعلی)
- JSON-LD: `Organization` و `WebSite` سراسری + `BlogPosting` برای مقالات + `Service` برای خدمات +
  `FAQPage` برای سؤالات متداول + `BreadcrumbList` برای همه صفحات
- `sitemap.xml` خودکار از `@astrojs/sitemap` — اکنون شامل **همه صفحات واقعاً منتشرشده**
  (در سایت فعلی ۴ اسلاگ قدیمی نمونه‌کار داخل sitemap بودند که به 404 می‌رفتند)
- `robots.txt` با Disallow همان `/admin` و `/api/` سایت فعلی
- Alt فارسی توصیفی برای تمام تصاویر

## کارایی و تجربه کاربری

- فونت Vazirmatn محلی با `preload` و `font-display: swap`
- تصاویر WebP + `loading="lazy"` برای همه تصاویر خارج از دید + ابعاد صریح برای کنترل CLS
- انیمیشن‌ها با IntersectionObserver سبک (بدون کتابخانه) + احترام کامل به `prefers-reduced-motion`
- افکت اسکرول کارت نمونه‌کار فقط با CSS transform (بدون JS سنگین)
- هدر قرصی شناور → چسبیدن نرم هنگام اسکرول (مطابق الگوی مرجع)
- فونت/کش هدرهای امنیتی و کش طولانی‌مدت در `vercel.json`

## استقرار روی Vercel

1. ریپو را به گیت پوش کنید (بعد از بازبینی نسخه استاتیک).
2. در Vercel متغیرهای محیطی را از `.env.example` تنظیم کنید.
3. `npm run build` به‌عنوان Build Command و آداپتور `@astrojs/vercel` (از قبل در `astro.config.mjs` فعال است).
4. دامنه cdanesh.ir را مانند قبل متصل نگه دارید — هیچ تغییری در DNS لازم نیست.
5. بعد از اولین استقرار، یک‌بار `psql "$DATABASE_URL" -f db/schema.sql` را اجرا کنید (اگر جداول موجود نیستند).
