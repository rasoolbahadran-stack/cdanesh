# کافه دانش (Cafe Danesh) — وب‌سایت Astro و پنل مدیریت ابری

> **تغییرات مهم این نسخه (۳۱ اکتبر ۲۰۲۶):**
> 1. **رفع خطای 403 آپلود رسانه** — علت: بررسی CSRF پیش‌فرض Astro روی ورسل، همهٔ آپلودهای multipart را می‌بست (`security.checkOrigin: false` در astro.config).
> 2. **دروازهٔ پرداخت برای هر پکیج جدا شد** — در بخش «درگاه پرداخت» پنل، ستون «پکیج مرتبط» اضافه شد؛ برای استارتر/حرفه‌ای/فروشگاهی/اختصاصی می‌توانی ۴ لینک پرداخت با مبلغ خودشان ثبت کنی. تا وقتی درگاهی فعال نشده، دکمه‌های پرداخت سایت مخفی‌اند (لینک مرده نداریم).
> 3. **اعلان فوری تلگرام** — با تنظیم دو متغیر محیطی `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` (راهنمای کامل داخل پنل → تنظیمات)، هر پیام/درخواست مشتری همان لحظه به تلگرامت می‌آید. در بخش پیام‌های پنل هم دکمهٔ «پاسخ در واتس‌اپ» برای جواب سریع به هر مخاطب اضافه شد.
> 4. **فرم‌ها فقط بعد از ذخیرهٔ واقعی روی سرور پیام «ثبت شد» می‌دهند** — دیگر هرگز پیام موفقیت دروغ نمی‌بینی؛ در صورت خطا، شمارهٔ تماس جایگزین نشان داده می‌شود.
> 5. **حالت کد ویرایشگر (</>) حالا HTML/CSS/JS کامل را نگه می‌دارد** — تگ‌های `<style>` و `<script>` برای محتوای خودت حذف نمی‌شوند (مثل بلوک HTML گوتنبرگ). برای حفظ کدها، در حالت کد ذخیره/منتشر کن.
> 6. **اصلاح خودکار متن‌های قدیمی نسخهٔ ابری** — در بخش مقالات پنل، اگر نسخهٔ ابری هنوز ادعای «نصف تلاش»، نام نویسندهٔ قدیمی یا تاریخ آیندهٔ مقالهٔ تعرفه‌ها را داشته باشد، بنر «اصلاح خودکار» ظاهر می‌شود؛ یک کلیک همه را درست و در ابر ذخیره می‌کند.
> 7. **تعرفه‌ها**: استارتر ۳ ماه، حرفه‌ای ۶ ماه، فروشگاهی و اختصاصی یک سال هاست هدیه + دامنهٔ .IR رایگان برای همه. متن تناقض‌دار قیمت در صفحهٔ FAQ هم اصلاح شد.
> 8. **صفحهٔ مقاله**: نویسندهٔ واقعی (رسول بهادران + تخصص + جعبهٔ نویسنده با عکس)، اسکیمای Person، فهرست مطالب چسبیدهٔ سمت چپ تا فوتر. ریدایرکت 301 از `/article?slug=…` و ریدایرکت www→دامنهٔ اصلی در همان تنظیمات قبلی فعال است؛ sitemap.xml خودکار مقالات ابری را هم دارد.

سایت کامل کافه دانش با [Astro](https://astro.build) — همهٔ صفحات **استاتیک و سریع**، اما مجله، صفحات مقاله‌ها، صفحات ابری، نقشهٔ سایت و APIهای پنل **سمت سرور رندر می‌شوند**: هر مقاله یا صفحه‌ای که در پنل «انتشار» می‌شود، همان لحظه با HTML واقعی برای **همهٔ بازدیدکنندگان و گوگل** قابل خواندن است (بدون نیاز به جاوااسکریپت).

---


> **وضعیت فنی فعلی:** این مخزن بر پایهٔ Astro SSR، Vercel و PostgreSQL (Neon در Production) است. اشاره‌های قدیمی به مهاجرت Next.js، Prisma یا SQLite مربوط به مسیر تاریخی پروژه‌اند و وضعیت فعلی کد نیستند؛ تنظیمات و وابستگی‌های فعال را از `package.json`، `astro.config.mjs` و `src/lib/db.ts` بررسی کن.

## ۱) اجرا روی سیستم خودت

پیش‌نیاز: [Node.js](https://nodejs.org) نسخه ۱۸ یا بالاتر

```bash
npm install      # نصب وابستگی‌ها (فقط یک بار)
npm run dev      # اجرای محلی روی http://localhost:4321
npm run build    # ساخت خروجی نهایی در dist/
```

## ۲) انتشار — مخزن گیت‌هاب + ورسل (همان مسیر فعلی)

با هر push به مخزن `rasoolbahadran-stack/cdanesh`، ورسل خودش سایت را می‌سازد و منتشر می‌کند (۲–۳ دقیقه). دامنهٔ cdanesh.ir قبلاً متصل است.

**به‌روزرسانی با GitHub Desktop:** محتوای پوشهٔ `cdanesh-astro` داخل ZIP (نه خود پوشه) را داخل مخزن کلون‌شده کپی کن (به‌جز پوشهٔ پنهان `.git`) → Commit → Push. پوشهٔ `node_modules` را جابه‌جا نکن.

## ۳) فعال‌سازی انتشار واقعی (یک‌بار — مهم‌ترین گام)

> **پنل خودش راهنمایی می‌کند:** وقتی وارد `/admin` شوی و فضای ابری وصل نباشد، بنر زرد راهنمای سه‌گامی بالای داشبورد نمایش داده می‌شود.

| گام | کجا | چه کار |
|---|---|---|
| ۱ | ورسل → پروژه → تب **Storage** | **Create Database** → نوع **Blob** → نام `cdanesh-content` → **Connect** به همین پروژه |
| ۲ | تب **Settings → Environment Variables** | متغیر `ADMIN_PASSWORD` با یک رمز قوی (حداقل ۱۰ کاراکتر) — تیک Production و Preview → Save |
| ۳ | تب **Deployments** | آخرین دیپلوی → **⋯ → Redeploy** |

بعد از ۲–۳ دقیقه: خروج از پنل → ورود با `admin` و رمز ابری. نشان ذخیره‌سازی باید «ابری (واقعی)» شود. تا قبل از آن، پنل در حالت دمو است و تغییرات فقط در همان مرورگر ذخیره می‌شود.

## ۴) امکانات پنل مدیریت (`/admin`)

| بخش | توضیح |
|---|---|
| **داشبورد** | آمار کلی + نمودار ۱۴ روزهٔ پیام‌ها + نمودار دسته‌بندی مقالات |
| **مقالات** | ویرایشگر حرفه‌ای WYSIWYG + حالت کد HTML؛ دکمهٔ «انتشار»؛ زمان‌بندی؛ پیش‌نویس |
| **رسانه** | کتابخانه رسانه مثل وردپرس: آپلود تصویر/فایل در تب «🖼» ویرایشگر یا هنگام انتخاب تصویر شاخص؛ تصاویر بزرگ خودکار به WebP فشرده می‌شوند؛ کپی لینک و حذف |
| **تصویر شاخص** | انتخاب آزاد از کتابخانه رسانه یا هر آدرسی + فیلد Alt |
| **صفحات** | «صفحات ابری»: افزودن صفحه جدید (منتشر در `/p/<slug>`)؛ «شرایط استفاده» و «حریم خصوصی» هم از همین‌جا ویرایش می‌شوند؛ تب دوم: سئوی صفحات ثابت |
| **پیام‌ها** | پیام فرم تماس، درخواست مشاوره و درخواست پکیج + بودجهٔ اعلامی مشتری؛ وضعیت جدید/خوانده/پاسخ‌داده‌شده؛ خروجی JSON |
| **درگاه پرداخت** | ثبت لینک درگاه واسط (زرین‌پال و…)؛ دکمه‌های پرداخت سایت به همان لینک وصل می‌شوند |
| **سؤالات متداول** | سؤال و پاسخ هر صفحهٔ خدمت؛ ترتیب و فعال/غیرفعال |
| **تنظیمات** | **تغییر نام کاربری و رمز عبور از خود پنل** (نشست‌های دستگاه‌های دیگر خودکار بسته می‌شود) |

**آدرس‌های مقاله:** هر مقاله در `/blog/<slug>` منتشر می‌شود و لینک «مشاهده در سایت» در فهرست مقالات همان را باز می‌کند. آدرس‌های قدیمی `/article?slug=…` به آدرس تمیز ریدایرکت ۳۰۱ می‌شوند.

## ۵) سئو

- **نقشهٔ سایت خودکار:** `cdanesh.ir/sitemap.xml` — مقالات ابری و صفحات ابری بلافاصله اضافه می‌شوند.
- **Robots:** `cdanesh.ir/robots.txt`
- **دادهٔ ساختاریافته:** Organization، Article، BreadcrumbList و FAQPage (سؤالات صفحات خدمات داخل HTML واقعی صفحه است).
- **عنوان‌های سئو** صفحات اصلی/خدمات با کلمات کلیدی هدف (طراحی سایت در بوشهر و…).
- **نام سایت در گوگل:** صفحهٔ اصلی دارای دادهٔ ساختاریافتهٔ `WebSite` با نام اصلی `کافه دانش` و نام لاتین جایگزین `Cafe Danesh` است؛ `og:site_name` و اسکیمای `Organization` نیز با همین هویت هماهنگ‌اند. پس از انتشار، در [Google Search Console](https://search.google.com/search-console) → URL Inspection آدرس `https://cdanesh.ir/` را بررسی و `Request Indexing` را ثبت کن. انتخاب Site Name نهایی خودکار است و ممکن است پس از خزش مجدد چند روز تا چند هفته زمان ببرد.

## ۶) نکته‌های امنیتی

- رمز مدیر فقط به‌صورت هش (pbkdf2) در فضای ابری ذخیره می‌شود؛ در کد نیست.
- محدودیت تلاش ورود، نشست ۷ روزهٔ امضاشده (HMAC)، تلهٔ اسپم و محدودیت نرخ فرم‌ها فعال است.
- هدرهای امنیتی (X-Frame-Options، nosniff، Referrer-Policy و…) در `vercel.json` تنظیم شده‌اند.
- **در ورسل چیز خاصی لازم نیست تیک بخوری:** فقط مطمئن شو «Deployment Protection» خاموش است (سایت عمومی بماند) و Blob + `ADMIN_PASSWORD` مطابق گام ۳ تنظیم باشند.

## ۷) ساختار پروژه

```
src/pages/          صفحات سایت (استاتیک) + blog/[slug] + p/[slug] + api/*  (SSR)
src/lib/            منطق SSR مقالات و صفحات ابری
src/data/           دادهٔ پایهٔ مقالات، FAQ، صفحات پایه
server/handlers/    APIهای ابری (مقالات، پیام‌ها، درگاه، صفحات، ورود)
public/assets/      CSS / JS / فونت / تصاویر (WebP)
```

## ۸) پس از استقرار — چک‌لیست تست

1. ورود به `/admin` با رمز ابری → نشان «ابری (واقعی)».
2. یک مقالهٔ تستی بنویس و «انتشار» بزن → در دستگاه/مرورگر دیگری `/blog` را باز کن — مقاله باید همین لحظه دیده شود.
3. از فرم «درخواست مشاوره» یک پیام تست بفرست → بخش «پیام‌ها» پنل.
4. یک صفحهٔ جدید بساز → لینک `/p/<slug>` را در مرورگر ناشناس باز کن.
5. PageSpeed Insights برای `/` و `/web-design`.

## ۹) هات‌فیکس ۳۰ آبان ۱۴۰۵ — رفع خطای 500 مجله و 504 ذخیرهٔ پنل

**مشکل اول (500 روی مجله):** تمام صفحات رندر سمت سرور (مجله، مقاله، نقشهٔ سایت، حریم خصوصی، شرایط استفاده) یک تابع سروری مشترک دارند. اگر هر مشکلی در مسیر خواندن دادهٔ ابری پیش می‌آمد، کل صفحه با خطای `FUNCTION_INVOCATION_FAILED` از دست می‌رفت. اصلاح شد: import کتابخانهٔ Blob در صفحات «تنبل» و کاملاً محافظت‌شده شد و هر فراخوانی شبکه سقف ۴ ثانیه دارد — حالا حتی اگر فضای ابری موقتاً در دسترس نباشد، صفحه با دادهٔ همراه پروژه رندر می‌شود و هرگز 500 نمی‌شود.

**مشکل دوم (504 ذخیرهٔ پنل):** سقف اجرای توابع روی پلن رایگان ۱۰ ثانیه است؛ ذخیرهٔ بزرگ (شروع سرد + چند رفت‌وبرگشت به Blob) گاهی از آن رد می‌شد. اصلاح شد: سقف اجرا در `astro.config.mjs` روی ۶۰ ثانیه تنظیم شد، همهٔ فراخوانی‌های Blob سقف ۸ ثانیه‌ای گرفتند (دیگر هیچ‌چیز معلق نمی‌ماند) و پنل روی خطاهای گذرا خودکار یک بار دوباره تلاش می‌کند.

## ۱۰) نسخهٔ ۲ — تضمین دسترسی مدیر (کلید اضطراری)

- رمز مدیر فقط در ورسل (Environment Variables → ADMIN_PASSWORD به‌صورت Secret) نگهداری می‌شود و در هیچ فایل کد یا ZIP نیست.
- تضمین ورود: حتی اگر اطلاعات ابری (users.json) قدیمی یا متفاوت باشد، رمز ورسل همیشه به‌عنوان کلید اضطراری کار می‌کند — با هیچ تغییری از پنل بیرون نمی‌مانید.
- تغییر نام کاربری/رمز از خود پنل (تنظیمات → تغییر نام کاربری و رمز عبور) هم فعال است؛ اگر استفاده کنید، رمز جدید در فضای ابری با هش ذخیره می‌شود و رمز ورسل همچنان کلید اضطراری می‌ماند.
