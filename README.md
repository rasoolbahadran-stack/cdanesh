## ۱. پیش‌نیازها

- **Node.js نسخه ۲۰ یا بالاتر** (یا Bun نسخه ۱.۳+)
- دسترسی به اینترنت برای نصب وابستگی‌ها

## ۲. نصب و اجرا

```bash
# ۱) استخراج ZIP و ورود به پوشه پروژه
unzip cdanesh-redesign.zip
cd cdanesh-redesign

# ۲) ساخت فایل محیطی از روی نمونه
cp .env.example .env

# ۳) نصب وابستگی‌ها
#    با npm:
npm install
#    یا با bun:
bun install

# ۴) همگام‌سازی دیتابیس (اگر فایل db/custom.db موجود است، نیازی به این مرحله نیست)
npx prisma db push

# ۵) (اختیاری، فقط برای دیتابیس خالی) داده‌های اولیه: مدیر، ۱۴ مقاله، ۶ نمونه‌کار، ۹ پکیج، FAQ صفحات
npx tsx prisma/seed.ts
#    یا: bun prisma/seed.ts

# ۶) اجرای محیط توسعه
npm run dev        # http://localhost:3000

# ۷) اجرای نسخه تولید (Production)
npm run build
npm run start
```

> اگر فایل `db/custom.db` را همراه پروژه کپی کرده باشید، تمام محتوای اولیه (مقالات، نمونه‌کارها، دسته‌بندی‌ها و کاربران) از قبل موجود است و Seed لازم نیست.

## ۳. ورود به پنل مدیریت

| مورد | مقدار |
|---|---|
| آدرس ورود | `/admin/login` |
| نام کاربری | `admin` |
| رمز عبور | ⚠️ **در فایل خصوصی جداگانه `ADMIN-LOGIN-INFO.txt`** — همراه ZIP تحویل شده اما عمداً داخل ZIP نیست |

⚠️ **بلافاصله پس از اولین ورود، رمز را تغییر دهید:** منوی «حساب من» ← «تغییر رمز عبور».

این سند و سورس‌کد عمداً هیچ رمز واقعی‌ای ندارند؛ رمز به‌صورت هش امن (scrypt) در دیتابیس ذخیره می‌شود. برای ساخت کاربران دیگر (مدیر محتوا/نویسنده) پس از ورود، از بخش «کاربران» پنل استفاده کنید.

نقش‌ها:
- **مدیر کل (ADMIN):** دسترسی کامل شامل مدیریت کاربران، پکیج‌ها و تعرفه و تنظیمات
- **مدیر محتوا (EDITOR):** مدیریت مقالات، رسانه‌ها، نمونه‌کارها، دسته‌بندی‌ها، درخواست‌ها و ریدایرکت‌ها
- **نویسنده (AUTHOR):** ایجاد و ویرایش مقاله‌های خودش

## ۴. متغیرهای محیطی

همه متغیرها در فایل `.env.example` با توضیح آمده است. خلاصه:

| متغیر | توضیح | پیش‌فرض |
|---|---|---|
| `DATABASE_URL` | مسیر دیتابیس SQLite (نسبت به پوشه `prisma/`) | `file:../db/custom.db` |
| `NEXT_PUBLIC_SITE_URL` | آدرس عمومی سایت برای canonical و sitemap | `https://www.cdanesh.ir` |
| `ADMIN_PASSWORD` | رمز مدیر فقط در اولین Seed (اختیاری) | رمز قوی تصادفی → فایل خصوصی |
| `NODE_ENV` | محیط اجرا | `production` در استقرار |
| `ZARINPAL_MERCHANT_ID` … | کلید درگاه پرداخت — فقط بعد از قرارداد واقعی | خالی (پرداخت غیرفعال) |

برای تغییر دامنه و اطلاعات تماس، نیازی به تغییر کد نیست؛ از پنل مدیریت ← «تنظیمات سایت» مقادیر را به‌روز کنید. (اطلاعات پایه برند در `src/lib/site.ts` نیز قابل ویرایش است.)

## ۴-۱. قیمت‌گذاری و درگاه پرداخت

- **دروازهٔ تأیید قیمت (فعال):** قیمت‌های طراحی سایت با تأیید مالک (۸ آبان ۱۴۰۵) نهایی و فعال‌اند: استارتر ۱۵ میلیون، حرفه‌ای ۱۹ میلیون، فروشگاهی ۴۰ میلیون و پکیج اختصاصی «شروع از ۷۰ میلیون (دریافت برآورد قیمت)». سئو/محتوا/AI فعلاً بدون قیمت و فقط «دریافت برآورد قیمت» هستند. تغییر حالت (برآوردی/نهایی) و همه اعداد از مسیر پنل ← «پکیج‌ها و تعرفه» قابل ویرایش است؛ در حالت «برآوردی» هیچ قیمتی در سایت نمایش داده نمی‌شود.
- **مدیریت پکیج‌ها:** پنل ← «پکیج‌ها و تعرفه» — ساخت/ویرایش/نمایش/پنهان‌کردن، قیمت، مدت، پشتیبانی، امکانات و لینک درخواست (`?pkg=slug`).
- **ساختار پرداخت:** مدل `Order` (شماره سفارش، مبلغ، وضعیت، درگاه، `callbackVerified`) آماده است؛ تأیید تراکنش فقط سمت سرور با API رسمی درگاه انجام می‌شود و به پارامترهای مرورگر اعتماد نمی‌شود. تا زمانی که کلید درگاه در `.env` قرار نگیرد، پرداخت واقعی فعال نیست و هیچ ادعایی هم در سایت نمی‌شود.

## ۵. اتصال هوش مصنوعی

ابزارهای هوش مصنوعی سایت (۸ ابزار عمومی در `/ai-tools` و تولید مقاله در پنل) از طریق **لایه سرور** به مدل زبانی متصل می‌شوند؛ کلید API هرگز به مرورگر ارسال نمی‌شود.

### لایه اتصال

فایل `src/lib/ai.ts` تنها نقطه اتصال به مدل است. برای تعویض ارائه‌دهنده فقط همین فایل را ویرایش کنید؛ بقیه سیستم (ابزارها، پنل، محدودیت‌ها) بدون تغییر کار می‌کند.

### پیکربندی پیش‌فرض (z-ai-web-dev-sdk)

پکیج `z-ai-web-dev-sdk` فایل پیکربندی را به این ترتیب جست‌وجو می‌کند:

1. `./.z-ai-config` (کنار پروژه)
2. `~/.z-ai-config` (پوشه خانه کاربر)
3. `/etc/.z-ai-config`

ساخت فایل:

```json
{
  "baseUrl": "https://YOUR-API-ENDPOINT/v1",
  "apiKey": "YOUR_API_KEY"
}
```

سپس سرویس را ری‌استارت کنید. برای بررسی سلامت اتصال، در پنل مدیریت ← «هوش مصنوعی» وضعیت را ببینید یا یکی از ابزارهای `/ai-tools` را اجرا کنید.

### امنیت و محدودیت‌ها

- کلید فقط در سمت سرور؛ در لاگ‌ها یا پاسخ‌ها منتشر نمی‌شود
- ابزارهای عمومی: حداکثر **۱۰ درخواست در ۱۰ دقیقه** برای هر IP
- تولید مقاله در پنل: حداکثر **۶ بار در ۱۰ دقیقه** برای هر کاربر
- ورودی‌ها سمت سرور اعتبارسنجی و محدود به طول مجاز می‌شوند
- Timeout پردازش: ۹۰ ثانیه (تولید مقاله ۱۸۰ ثانیه)
- **محتوای AI پیش از انتشار باید توسط نویسنده بازبینی شود** — این اصل در رابط کاربری هم تذکر داده شده است

## ۷. قابلیت‌ها و صفحات

**عمومی:** صفحه اصلی با بخش پکیج‌های دیتابیس‌محور (تب‌های طراحی/سئو و محتوا/هوش مصنوعی)، ۸ صفحه خدمات با FAQ داینامیک، وبلاگ با جست‌وجو/دسته‌بندی/برچسب/صفحه‌بندی، صفحه مقاله با فهرست مطالب خودکار و مقالات مرتبط، نمونه‌کارها با هوور اسکرول کامل صفحه (بدون ماسک، توقف دقیق در انتهای واقعی، بازگشت نرم) و نمای بزرگ، درباره ما، تماس، درخواست مشاوره با پیش‌انتخاب پکیج، حریم خصوصی، قوانین، ۴۰۴ اختصاصی.

**پنل مدیریت:** داشبورد آماری واقعی، مدیریت مقالات (ویرایشگر، پیش‌نویس/زمان‌بندی/انتشار، نسخه‌های قبلی، پیش‌نمایش گوگل)، تولید مقاله با AI، دسته‌بندی و برچسب، رسانه‌ها (آپلود با تبدیل خودکار WebP)، نمونه‌کارها، **پکیج‌ها و تعرفه با دروازهٔ قیمت**، **صفحهٔ سئو** (وضعیت متای همه صفحات + مدیریت ریدایرکت‌های سروری)، درخواست‌های مشتریان با وضعیت و یادداشت، کاربران و نقش‌ها، تنظیمات (برند/تماس/سئو/قیمت‌گذاری/درگاه)، گزارش فعالیت کامل، حساب من (تغییر رمز).

**سئو:** متادیتای اختصاصی هر صفحه، Canonical، Open Graph/Twitter، `sitemap.xml` و `robots.txt` خودکار، داده ساختاریافته (Organization، WebSite+SearchAction، Article، BreadcrumbList، FAQPage، Service)، هدینگ‌های سلسله‌مراتبی، لینک‌سازی داخلی، Alt تصاویر، جلوگیری از ایندکس پنل و API.

**فنی:** Next.js 16 + React 19 + TypeScript + Tailwind 4 + shadcn/ui + Prisma/SQLite، فونت Vazirmatn محلی، RTL کامل، تاریخ جلالی و اعداد فارسی، واکنش‌گرا در ۵ اندازه، احراز هویت با scrypt و نشست سمت سرور (کوکی httpOnly)، محافظت سروری از همه مسیرهای /admin و APIها، محدودیت نرخ، لاگ فعالیت، آپلود امن با تبدیل WebP.

## ۸. انتشار زمان‌بندی‌شده مقالات

مقالاتی با وضعیت «زمان‌بندی انتشار» در زمان مقرر به‌صورت **Lazy Publish** منتشر می‌شوند: اولین بازدیدِ بعد از زمان مقرر (صفحه وبلاگ، مقاله یا داشبورد پنل) یک به‌روزرسانی اتمی اجرا می‌کند که مقاله‌های رسیده را منتشر می‌کند. مزیت: بدون نیاز به cron خارجی روی هر هاستی کار می‌کند. اگر ترافیک سایت بسیار کم است و می‌خواهید انتشار دقیق‌تر باشد، می‌توانید یک cron خارجی به هر URL سایت هر ۱۵ دقیقه زد (مثلاً `curl https://yoursite.ir/blog`).

## ۹. استقرار روی هاست واقعی

پروژه یک اپ استاندارد Next.js است و روی هر هاستی که Node.js اجرا می‌کند بالا می‌آید:

```bash
npm run build
npm run start        # سرور روی پورت 3000
```

چک‌لیست استقرار:
1. فایل `.env` را با `DATABASE_URL` درست بسازید (مسیر دیتابیس پایدار و بکاپ‌پذیر)
2. `npx prisma db push` برای ساخت دیتابیس در صورت نبود فایل
3. پس از اولین استقرار، رمز کاربر `admin` را عوض کنید
4. HTTPS را با CDN/Reverse Proxy فعال کنید (کوکی نشست در production فقط Secure ارسال می‌شود)
5. در کنسول جست‌وجوی گوگل، دامنه واقعی را ثبت و `sitemap.xml` را معرفی کنید
6. دامنه در `src/lib/site.ts` (`SITE.url`) و متادیتای layout را با دامنه نهایی هماهنگ کنید

## ۱۰. نکات امنیتی

- رمزها با scrypt + نمک تصادفی هش می‌شوند؛ هرگز متن خام ذخیره نمی‌شود
- نشست‌ها توکن تصادفی ۴۸ بایتی هستند که هش‌شده در دیتابیس ذخیره و در کوکی httpOnly/SameSite=Lax ارسال می‌شوند؛ در production فقط Secure
- تمام مسیرهای `/admin` در لایه سرور (layout) و همه Server Actions/APIها مجدداً احراز هویت و نقش را بررسی می‌کنند
- ورود: حداکثر ۵ تلاش ناموفق در ۱۵ دقیقه برای هر IP
- تغییر رمز، همه نشست‌های دیگر کاربر را باطل می‌کند
- آپلود: فقط تصویر، حداکثر ۸MB، پردازش با sharp و ذخیره با نام تصادفی
- کاربر غیرفعال‌شده بلافاصله از همه نشست‌ها خارج می‌شود
- کلیدهای محرمانه فقط سمت سرور؛ در ZIP هیچ کلیدی وجود ندارد

## ۱۱. اقدامات باقی‌مانده برای مالک سایت

فایل `OWNER-INFO.md` را ببینید؛ شامل فهرست اطلاعاتی است که فقط مالک برند می‌تواند تأیید/تکمیل کند (شبکه‌های اجتماعی، آمار واقعی، لینک نمونه‌کارهای واقعی و...).
